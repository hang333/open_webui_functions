## 一、相对上游 2.1.0 的改动

### 1. 身份、打包与依赖

- 新的函数 id `gemini_manifold_plus`、标题「Gemini Manifold Plus」、版本 `2.2.0+plus.5`：可与上游管道并存，不会相互覆盖。管道不再假设自己的 id，模型名按「`<函数 id>.<模型 id>`」拆分（函数 id 不含 `-`，Gemini 模型 id 一定含 `-`），因此装成别的 id 也能工作。
- **模型表内嵌**：上游由伴随过滤器从 GitHub 下载 YAML；Plus 把 `gemini_models.yaml` 逐字嵌入管道，无需托管任何文件，也不依赖伴随过滤器。管道把模型表以 `gemini_model_config` 属性公开，新版伴随过滤器直接读取它做能力判断，两者永远一致。
- **为什么固定 `google-genai==3.3.0`**：
  1. 与上游 2.1.0 相同。Open WebUI 启动时把所有已启用函数的 `requirements` 合并成**一次** `pip install`；若两个函数固定了不同版本，pip 会因冲突整体失败。用同一版本，原版与 Plus 可以并存。
  2. 3.3.0 已具备本实现用到的全部能力（已在本地 3.3.0 中逐一核对字段）：`ThinkingLevel.XHIGH`（3.3.0 新增）、`ToolConfig.include_server_side_tool_invocations`、`Part.tool_call/tool_response`、`FunctionCallingConfigMode.VALIDATED`、`PartMediaResolution`（含 `ULTRA_HIGH`）、`GoogleSearch.search_types`（Image Search）、`FileSearch`、`GroundingChunk.image`、Interactions API 客户端（`client.aio.interactions.create/get/cancel`、`Interaction.output_video`）。
  3. 3.4.0–3.6.1 只有 2–8 天历史，带来的改动（Interactions 名称弃用、Live Interactions、continuation 修复）本实现不需要。
- 由 `Storage.get_file()` 读取文件，S3 / GCS / Azure / 本地存储都走 Open WebUI 自己的存储提供者；去掉了上游自写的 GCS 分支和 `google.cloud.storage`、`google.api_core` 依赖。
- 注意 Open WebUI 会把插件源码中任意位置的 `from utils` / `from apps` / `from main` / `from config` 改写成 `from open_webui.…`；测试保证源码里只有 `TYPE_CHECKING` 块中的那一处。

### 2. 模型列表与模型表

- 模型列表过滤掉非对话模型：TTS、Live、原生音频、转写、嵌入、机器人、Computer Use、Decision、Lyria、Imagen、Veo、Genie、AQA，以及只能走 Interactions API 的 Omni、Deep Research、Antigravity（见代码中 `NON_CHAT_MODEL_PATTERNS`）。表中没有的新对话模型（如 Gemma 4、`gemini-*-latest` 别名）仍会列出。
- Interactions-only 模型作为**虚拟模型**按管理员开关加入（见第 10 节）。
- `gemini_models.yaml` 的更新（依据 [models](https://aistudio.google.com/docs/models)、各模型页、[deprecations](https://aistudio.google.com/docs/deprecations)、[pricing](https://aistudio.google.com/docs/pricing)）：
  - 新增 `gemini-4-neon`（2026-11-18 GA，$3.00/$15.00/$0.15，仅付费层）。
  - 删除已关停的 `gemini-3-pro-preview`、`gemini-3.1-flash-lite-preview`、`gemini-2.0-flash`、`gemini-2.0-flash-lite`。
  - 新增 `thinking` 块：Gemini 3/4 及图像模型写 `levels`/`default`，Gemini 2.5 写 `budget`/`can_disable`。
  - 能力修正：`gemini-3.5-flash-lite`、`gemini-3.1-flash-lite`、`gemini-3-flash-preview`、`gemini-3.1-pro-preview(-customtools)` 支持 Maps；`gemini-3.1-flash-lite-image` 不支持函数调用；`gemini-3-pro-image`、`gemini-2.5-flash-image` 不支持结构化输出。
  - 图像选项：`gemini-3.1-flash-image` 的 0.5K 尺寸按文档写作 `"512"`；`gemini-3.1-flash-lite-image` 固定 1K、只有 10 种宽高比；新增 `max_reference_images`（2.1 / 3.1 Flash Image / 3 Pro Image 为 14）和 `image_search`（2.1 / 3.1 Flash Image）。
  - 价格：3.6 Flash 改为优惠价（至 2026-12-31），2.5 Pro 缓存价按 200k 分档，2.5 Flash / Flash-Lite 补上缓存价；为已弃用/改路由的模型加了注释（2.5 Pro → 3.8 Flash、2.5 Flash → 3.5 Flash-Lite，2026-12-01 起）。

### 3. 思考（thinking）

参考：[thinking](https://aistudio.google.com/docs/thinking.md?generate-content=true)、[openai#thinking](https://aistudio.google.com/docs/openai)。

- `THINKING_CONFIG_RULES`（及其同义词 `reasoning_effort`、`thinking_level`、`thinking_budget`）的写法与上游完全兼容，但结果会**按模型拟合**：
  - 有等级的模型（Gemini 3.x / 4、图像模型）只发 `thinking_level`，取该模型支持的最接近等级，平局向上取（例：Gemini 4 Carbon/Argon 的 `xhigh`→`high`、`minimal`→`low`；Neon/Hydrogen 支持 `xhigh`；3.8 Flash 无 `minimal`）。数值预算会先换算成等级。**Gemini 4 永远不会收到 `thinking_budget`**（Gemini 4 已弃用该字段，与等级同发会 400）。
  - Gemini 2.5 只发 `thinking_budget`，等级按 OpenAI 兼容层映射（minimal/low→1024、medium→8192、high/xhigh→24576），并截到模型区间（2.5 Pro 128–32768、2.5 Flash 0–24576、2.5 Flash-Lite 512–24576）。
  - 新值 `NONE`（即 `reasoning_effort: none`）与「Reason」开关关闭：能关闭思考的模型发预算 0，否则用最低等级/最小预算（Gemini 4 无法关闭思考）。上游在 Gemini 3+ 上会忽略关闭开关。
- 无效的 `reasoning_effort`（例如 `turbo`）不再让请求报错，而是记录警告并沿用管理员设置。
- `include_thoughts` 跟随 `SHOW_THINKING_SUMMARY`；模型表中无思考能力的模型不发送思考配置。

### 4. 请求形状

- **从不发送** `temperature`、`top_p`、`top_k`（2026-07-21 起弃用；3.6+ 忽略，Neon/Hydrogen 对越界值返回 400，将来会全部 400）以及 `candidate_count`/`n`（Gemini 3+ 不支持）。参考 [whats-new-gemini-3.6](https://aistudio.google.com/docs/whats-new-gemini-3.6.md?generate-content=true)。
- **从不以模型轮结尾**：Open WebUI 的「继续回答」会把未完成的助手消息放在最后；3.5 Flash-Lite、3.6 及以后模型会对这种预填充返回 400。此时追加一个要求「接着写、不要重复」的用户轮。
- 最后一个用户轮只有附件时补一句文本（3.8+ 要求最后用户轮含非空文本；上游只对 Vertex AI 这样做）。
- `max_tokens`（以及 OpenAI 风格的 `max_completion_tokens`）→ `max_output_tokens`；`stop` → `stop_sequences`。
- 始终设置 `automatic_function_calling.disable=True`：工具只由 Open WebUI 执行。

### 5. 原生工具调用（Open WebUI 0.13.4 原生工具循环）

参考：[function-calling](https://aistudio.google.com/docs/function-calling.md?generate-content=true)、[thought-signatures](https://aistudio.google.com/docs/thought-signatures.md?generate-content=true)、[tool-combination](https://aistudio.google.com/docs/tool-combination.md?generate-content=true)。这一部分参考了 owndev「Google Gemini Pipeline」v1.20.0（Apache-2.0）的思路（工具名映射、JSON Schema 清理、工具轮转换），未复制代码，全部按 Manifold 的结构重新实现（`ToolBridge` 类与 `GeminiContentBuilder` 中的工具轮处理），并在代码中注明了出处。owndev 的 `_is_gemini_3_family_model` 只匹配 `gemini-3`，本实现改用版本号解析（Gemini 4 与未带版本号的新模型都按 3+ 处理）。

- 已核对的 Open WebUI 契约：原生模式下（`params.function_calling` 不等于 `legacy`，0.13.4 默认）`body['tools']` 是 OpenAI 风格的函数规格；管道产出 `tool_calls` 增量后，Open WebUI 执行工具并以新消息（`assistant.tool_calls` + `tool` 消息）再次调用管道；管道在增量中返回的 `reasoning_details` 由 Open WebUI 存在该轮的 reasoning 项中，并在之后的请求里随**同一模型**的助手消息原样带回（不同模型会被剥离）。
- **声明**：工具名映射为合法的 Gemini 函数名（非法字符替换并加哈希后缀，无状态、可往返）；JSON Schema 走 `parameters_json_schema` 并做最小清理；重复声明跳过。0.13.4 的 Tool Search 通过 `call_tool` 分发器调用延迟工具，无需另行声明。
- **`tool_choice`**：`none`→NONE（保留声明，历史中的调用仍有效；Open WebUI 达到迭代上限时就这样要求最终回答）、`required`→ANY、指定函数→ANY+`allowed_function_names`、`auto`/缺省→API 默认（AUTO，组合内置工具时为 VALIDATED）。
- **思维签名精确往返**：每轮结束时把该轮模型内容（`types.Content`，含全部签名）存进一个 `reasoning_details` 项（格式 `gemini-manifold-content-v1`），并保证它在 `tool_calls` **之前**发出，Open WebUI 才会把它归到本轮。重放时：
  - 并行调用：FC1（带签名）、FC2、FR1、FR2 的顺序与签名位置与原样一致；
  - 顺序调用：每一步各自带回自己的签名；
  - 流式分片的纯文本会合并，带签名的分片绝不合并或改动；仅作展示的思考摘要不回传；
  - 没有存储内容的调用（例如 Open WebUI 自己插入的记忆/技能隐藏调用）在**当前轮**对 Gemini 3+ 使用文档给出的占位签名 `skip_thought_signature_validator`（已验证 SDK 会原样发送）；历史轮不受校验，不加占位；
  - 没有结果的调用、没有调用的结果都会丢弃（Gemini 两者都拒绝）；如被丢弃的是带签名的第一个调用，则对新的第一个调用加占位签名；
  - 用户编辑过的消息（可见文本与存储内容不符）退回到按文本 + `tool_calls` 重建，并提示。
- **内置工具 + 函数**：Gemini 3/4 且非 Vertex AI 时同时下发并设置 `tool_config.include_server_side_tool_invocations=True`；服务端工具产生的 `toolCall`/`toolResponse` 部件只在同样开启工具上下文循环的请求里回传。Gemini 2.5 与 Vertex AI 上内置工具优先、不声明函数（只有用户自选的工具被丢弃时才弹出提示，Open WebUI 内置工具被丢弃只记日志）。
- **后台任务**：标题、标签、追问、查询、自动补全等任务不带任何工具；上下文压缩（`context_compaction`）保留函数声明但模式为 NONE，使请求前缀与聊天请求一致以命中隐式缓存。**Legacy 模式**下不声明任何函数（工具由 Open WebUI 自己选择执行）。
- 图像模型不声明函数（避免 Open WebUI 内置的 `generate_image` 等工具与原生出图冲突）。
- 流式与非流式都支持：非流式返回带 `tool_calls`、`reasoning_details` 和 `finish_reason: tool_calls` 的 OpenAI 结构（0.13.4 只在流式路径执行原生工具，非流式结果交给 API 客户端）。
- 工具调用本身失败（`MALFORMED_FUNCTION_CALL` 等）且模型未输出任何文本时，给出一行说明，而不是留下空消息。

### 6. 用量（usage）

参考：[tokens](https://aistudio.google.com/docs/tokens.md?generate-content=true)、0.13.4 `utils/response.py`（`normalize_usage`/`merge_usage`）。

- 以 0.13.4 存储的形状输出：`input_tokens` = `prompt_token_count` + `tool_use_prompt_token_count`（含缓存命中部分），`output_tokens` = `candidates_token_count` + `thoughts_token_count`（思考按输出计费），`total_tokens`；同时给出 `prompt_tokens`/`completion_tokens` 别名（上下文压缩读取）、`cache_read_input_tokens`、`prompt_tokens_details.cached_tokens`、`completion_tokens_details.reasoning_tokens`，以及可累加的 `input_cost`/`output_cost`/`total_cost`。Open WebUI 会在工具循环的各轮之间累加这些字段。
- 费用修正：思考 token 计入输出费用（上游漏算）；工具提示 token 计入输入；分档价格按提示长度整体选档（上游按边际分段计算）；无缓存价时缓存 token 按输入价计。
- 保留上游的 `token_details`、`cost_details`、累计 token/费用（`cumulative_*`，现覆盖工具循环的所有轮次）和耗时字段。

### 7. Grounding 合规

参考：[terms#grounding-with-google-search](https://aistudio.google.com/docs/terms)、[google-search](https://aistudio.google.com/docs/google-search.md?generate-content=true)、[maps-grounding](https://aistudio.google.com/docs/maps-grounding.md?generate-content=true)。

- **Search Suggestions**：`searchEntryPoint.renderedContent` 原样（逐字节）放进 Open WebUI 的消息 embed。0.13.4 用沙箱 iframe（`srcdoc`、允许脚本与弹窗）渲染字符串 embed，这是唯一能不经 DOMPurify 修改就显示 Google HTML/CSS 的方式；外层只加了 `<base target="_blank">`（链接在新标签页打开，无中间页）和一个回报高度的脚本。脚本量的是 `body` 的高度：框内的文档至少和框一样高（未调整前是 iframe 默认的 150px），量文档的话框永远缩不回去，搜索建议下面会空出一大块（2.2.0+plus.3 修正）。每个有 grounding 的轮次一条，最多 5 条，以 `replace` 方式同时更新界面与数据库。
- **Google Maps 来源**：在该轮文本之后紧接着追加来源列表：每个来源（含 `placeAnswerSources.reviewSnippets`）都有标题、指向 `uri`/`googleMapsUri` 的一次点击可达链接和原样的「Google Maps」字样（用不换行空格防止折行）。
- 图像搜索的来源链接到包含图片的页面（`GroundingChunk.image.source_uri`），而不是图片本身（伴随过滤器 2.2.0）。
- 只把**最后一轮**的 grounding 留给伴随过滤器加引用标记；伴随过滤器 2.2.0 只在最后一个消息输出项上插入标记（上游在多轮输出中会把整段文本写进每个消息项）。

### 8. 图像生成与编辑

参考：[image-generation](https://aistudio.google.com/docs/image-generation.md?generate-content=true)。

- `IMAGE_RESOLUTION` 增加 `512`（兼容旧写法 `512PX`/`0.5K`），宽高比与尺寸按模型表校验：不支持的值**不发送**并提示（上游会照发；另修复了未设置宽高比时每次都弹警告的问题）。
- 输入图片超过模型的参考图上限（14 张）时丢弃最旧的并提示。
- 开启 Google 搜索时，支持的模型（Nano Banana 2.1、3.1 Flash Image）同时使用 Image Search（`IMAGE_SEARCH` 阀门，默认开）。
- 多轮编辑：生成的图片存入 Open WebUI 文件并关联到聊天（共享聊天的参与者也能看到）；重放时连同 `thought_signature` 以原始字节送回。

### 9. 媒体分辨率、结构化输出、File Search

- `MEDIA_RESOLUTION`（LOW/MEDIUM/HIGH/ULTRA_HIGH）：前三者作为全局 `media_resolution`；`ULTRA_HIGH` 仅以单部件（per-part）方式用于 Gemini 3+ 的图片，其余媒体用 HIGH。参考 [media-resolution](https://aistudio.google.com/docs/media-resolution.md?generate-content=true)。
- `body['response_format']`：`json_schema` → `response_mime_type="application/json"` + `response_json_schema`；`json_object` → 仅 MIME 类型。Gemini 3/4 可与工具同用；Gemini 2.5 上结构化输出优先，不再声明函数。参考 [structured-output](https://aistudio.google.com/docs/structured-output.md?generate-content=true)。
- File Search：`FILE_SEARCH_STORE_NAMES`（逗号分隔的 `fileSearchStores/...`）与 `FILE_SEARCH_METADATA_FILTER`（AIP-160）。按文档它不能与其他内置工具同用：当一条消息开启了搜索/URL 上下文/地图/代码执行时，这些开关优先并提示；可与函数调用组合。仅 Gemini Developer API。参考 [file-search](https://aistudio.google.com/docs/file-search.md?generate-content=true)。

### 10. Interactions API 虚拟模型（可选，默认关闭）

参考：[interactions-overview](https://aistudio.google.com/docs/interactions-overview.md)、[deep-research](https://aistudio.google.com/docs/deep-research.md)、[background-execution](https://aistudio.google.com/docs/background-execution.md)、[omni](https://aistudio.google.com/docs/omni.md)。

- **Deep Research**（`ENABLE_DEEP_RESEARCH`）：`deep-research-preview-04-2026`、`deep-research-max-preview-04-2026`。以 `background=True, store=True` 启动，每 10 秒轮询，状态栏显示进度，思考摘要以推理内容实时显示；完成后输出报告、图表（存为文件）和带链接的来源；用户点击停止、超时（70 分钟）或轮询出错时调用 `interactions.cancel`，避免后台继续计费。交互 id 存在 `reasoning_details` 中（格式 `gemini-manifold-interaction-v1`），后续消息通过 `previous_interaction_id` 接着研究。
- **Omni 视频**（`ENABLE_OMNI_VIDEO`）：`gemini-omni-1.2-flash`，`response_format` 为 video（`OMNI_VIDEO_ASPECT_RATIO`、`OMNI_VIDEO_RESOLUTION`、`OMNI_VIDEO_DURATION` 3–15 秒），`delivery: uri`（大于 4 MB 的视频需要）后经 Files API 下载；视频存入 Open WebUI 文件、作为附件挂到消息上并在正文中以播放器显示；后续消息通过 `previous_interaction_id` 编辑或延长视频。
- 两者都只在管理员开启后出现并可调用，仅 Gemini Developer API。

### 11. 伴随过滤器 2.2.0（向后兼容）

- 同时识别 `gemini_manifold_google_genai.` 与 `gemini_manifold_plus.` 前缀；若已加载的管道公开 `gemini_model_config`（Plus 会），则用该内嵌表做能力判断、不下载 YAML，也不写入 `gemini_model_config` 应用状态（原版管道仍按旧方式下载并写入）。
- 图像搜索来源、只给最后一轮加引用标记（见第 7 节）。
- 宽松安全设置改为文档列出的 4 个类别全部 `OFF`；删除只适用于已关停的 1.x/2.0 模型的分支（含 civic integrity）。参考 [safety-settings](https://aistudio.google.com/docs/safety-settings.md?generate-content=true)。
- 版本号保持纯数字（2.2.0），原版管道的版本检查不会报错；切换器过滤器（Reason、URL Context、Google Maps Grounding、Paid API、Vertex AI）**未改动**，契约（函数 id、`filter_ids`）不变。

### 12. 健壮性与降级

- 不安装伴随过滤器也能工作：模型表内嵌、无需等待应用状态（上游会等 10 秒后报致命错误）；此时没有状态/提示消息、引用、搜索拦截和 RAG 绕过（Open WebUI 原生模式会改为提供它自己的网页搜索工具），错误仍以消息块显示在聊天中。
- 历史对齐：不再要求数据库消息数与请求消息数严格相等（工具轮与上下文压缩下必然不等，上游会因此退回且每次弹警告），改为从末尾配对用户消息，跳过 Open WebUI 自己插入的消息（工具图片消息、引导式重新生成提示）。
- 读取历史文件前按 Open WebUI 自己的规则检查读取权限（所有者、管理员或 `has_access_to_file`）。
- 不再把 `gemini_parts` 写回数据库：助手轮的高保真重放改由 Open WebUI 原生的 `reasoning_details` 承载，因此临时聊天、工具循环中的轮次、上下文压缩后也成立。

### 13. 安全：base URL 仅管理员可设（2.2.0+plus.2）

- 上游把 `GEMINI_API_BASE_URL` 放在用户可覆盖的阀门里：普通用户可以在自己的 UserValves 或对话参数里改掉它，而请求仍带着管理员填的 API key，key 就会被发到用户指定的服务器。Plus 把它移到仅管理员的 `Pipe.Valves`：UserValves 里不再有这个字段，以前保存的用户值和请求参数里的同名值都会被忽略（后者会记一条警告）。
- 用户自带 key 时也一样走管理员设的 base URL。
- 填法：Gemini 原生 API 的反代根地址（如 `https://gemini.example.com`，不带 `/v1beta`，不能是 OpenAI 兼容地址）；对话、模型列表、Files API 上传与 Interactions 请求都会走它，反代需转发 `/v1beta/...` 和 `/upload/v1beta/files`。使用 Vertex AI 时不生效。
- 驼峰命名（2.2.0+plus.4）：SDK 会把几个对象原样写进请求，字段用的是蛇形命名，如工具定义的 `parameters_json_schema`、思考配置的 `thinking_level` 与 `include_thoughts`、消息里文件的 `file_uri`。Google 两种写法都认，但按 REST 规范解析的反代可能只认驼峰；AxonHub 的原生 Gemini 端点就会丢掉它们，结果是工具没有参数、思考设置失效、文件丢了地址。因此设了 base URL 时，消息内容、工具和思考配置会改用驼峰命名、经 `http_options.extra_body` 发送（测试核对过：与 SDK 原本的请求只差字段命名）。直连 Google 时请求不变。
- YouTube 链接（2.2.0+plus.5）：`PARSE_YOUTUBE_URLS` 开启时，消息里的 YouTube 链接会被转成视频片段，现在两种 API 都带 `video/mp4` 类型。Vertex AI 不接受没有 MIME 类型的 `fileData`（报 400 "empty mimeType parameter in fileData"），而 AxonHub 的 Vertex 渠道会把 Gemini API 请求转给 Vertex。注意这个开关一开，凡是出现链接的消息都会把整段视频送给模型；URL 上下文工具不支持 YouTube，模型没法自己按需去看。

## 三、已知限制

- **Search Suggestions 的位置**：Open WebUI 0.13.4 把 embed 放在消息正文**上方**（状态栏之后），无法放到正文下方；非流式请求只有在 Open WebUI 提供事件发射器时才会显示（纯 API 客户端看不到）。
- **Maps 署名**：聊天消息中的原始 HTML 不会被渲染，所以署名是 Markdown，无法加 `translate="no"`，字体和颜色沿用 Open WebUI 正文样式。
- **空的推理块**：Open WebUI 只把 `reasoning_details` 存在 reasoning 项里。关闭思考摘要后，带工具调用、grounding、图片或代码执行的轮次会显示一个空的「Thought for 0 seconds」；纯文本回答的可选文本签名在这种情况下不保存，以免每条消息都出现空块。
- **工具结果中的图片**：Open WebUI 把各工具结果的图片合并成其后的一条用户消息，无法得知图片属于哪个调用，因此不使用 Gemini 3+ 的多模态函数响应，而按该用户消息发送。
- **临时聊天**：前端发来的历史不含 `output`/`reasoning_details`，之前的助手轮按文本重放（签名对历史轮不是必需的）；同一回答内的工具循环不受影响。
- 模型表之外的模型：不发送思考配置；搜索、代码执行、地图默认视为可用，URL 上下文默认不可用。
- 累计用量与 Search Suggestions 的跨轮状态保存在进程内存中（1 小时过期）；多 worker 部署时，同一回答的各轮总在同一请求中执行，不受影响。
- Deep Research：报告的引用以来源列表给出，不在正文中插入标记；Interactions API 的费用不计算（无按 token 的公开单价）。Omni：同步生成，请求一旦发出无法在服务端取消；编辑上传的视频在 EEA/瑞士/英国不可用；同样会出现空推理块（用来保存交互 id）。
- 伴随过滤器通过 Open WebUI 的内部属性 `app.state.FUNCTIONS` 读取 Plus 的模型表；若将来改名，会退回下载 `MODEL_CONFIG_PATH`。
- Gemini 4 的长解码（>65,536 输出 token）依赖 SDK 的自动续写，未单独处理和测试；Carbon/Argon 的非流式请求默认上限是 32,768。
- 未覆盖 Live API、TTS、嵌入、Computer Use、Batch API、显式缓存（Gemini 4 不支持显式缓存）。

## 五、与任务说明中「文档发现」的出入

- Omni 的模型 id 是 `gemini-omni-1.2-flash`（`gemini-omni-flash` 只是文档页名）；它替代的是 Veo；Imagen 的替代是 `gemini-nano-banana-2.1`（generateContent 模型）。文档只是暗示 Omni 仅限 Interactions API，没有明说。
- Interactions API 的 `Api-Revision: 2026-05-20` 头自 2026-06-08 起已被忽略，并非必需；响应字段是 `steps` 而不是 `outputs`。
- 采样参数：Gemini 4、3.6+ 与 3.5 Flash-Lite 会忽略；Neon/Hydrogen 对越界值返回 400；更早的 3.x 文档未说明会忽略。预填充 400 同样适用于 3.5 Flash-Lite；3.8 还要求最后用户轮含非空文本。
- 内联请求上限是 100 MB（PDF 50 MB），不是约 20 MB（图片/视频页面仍写 20 MB）。
- 文档只列出 4 个安全类别，没有 jailbreak 类别（SDK 枚举里有 `HARM_CATEGORY_JAILBREAK`）。
- 文档给出两个占位签名：`skip_thought_signature_validator` 和 `context_engineering_is_the_way_to_go`。
- 0.5K 尺寸写作 `"512"`，只有 3.1 Flash Image 支持；3.1 Flash-Lite Image 固定 1K、页面称 14 种宽高比但只列出 10 种；2.5 Flash Image 没有 `image_size`；14 张参考图只适用于 2.1、3.1 Flash Image、3 Pro Image，且有按类型的子上限。3.1 Flash Image 已弃用但没有关停日期。
- `reasoning_effort` 映射：Gemini 4 上 `minimal`→`low`；`xhigh` 只有 Neon/Hydrogen；`none` 只适用于能关闭思考的 2.5。3 Flash Preview 默认等级是 high，3.8 Flash 默认 medium。
- 搜索计费：每月 5,000 次是付费层额度、Gemini 3+ 共享，另有每天 1,500 次上限；Gemini 3+/4 的免费层不提供 Search/Maps。
- File Search 页面称不能与其他内置工具组合，而工具组合页面列出了它；本实现按更严格的说法处理。结构化输出的 REST 字段是 `responseFormat.text`（Python 仍为 `response_json_schema`）。
- Deep Research：最长 60 分钟、多数 20 分钟内完成，费用约 $1–3（标准）/ $3–7（Max），需要 `store=True`；`deep-research-pro-preview-12-2025` 已于 2026-10-23 关停。Omni 没有文档化的后台模式。
- 上游 YAML 缺少 2026-11-18 GA 的 `gemini-4-neon`，并仍包含已关停模型。
